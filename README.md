# Оценка свежести продуктов

Автор: Тимонин Андрей Сергеевич

## Постановка задачи

Цель проекта — создание программного решения, способного оценивать степень
свежести продукта по его визуальным данным.

### Зачем это нужно?

Разрабатываемая система может быть применена в следующих сферах:

1. **Для розничных покупателей.** Интеграция системы в мобильное приложение
   позволит потребителям в режиме реального времени проверять свежесть продуктов
   непосредственно в магазине. Это способствует принятию обоснованных решений о
   покупке и повышает стандарты потребления.
2. **Для ритейла и логистики.** Супермаркеты и дистрибьюторы смогут
   автоматизировать процесс входного контроля качества. Система позволит быстро
   сортировать партии продуктов по степени свежести, оптимизируя ротацию
   запасов, снижая финансовые потери и минимизируя риски продажи некачественного
   товара.
3. **Для пищевой промышленности.** Внедрение решения в производственные линии
   обеспечит дополнительный уровень контроля качества сырья. Стабильный
   мониторинг состояния продуктов позволит поддерживать высокие стандарты
   выпускаемой продукции.
4. **Для ресторанного бизнеса.** Шеф-повара и поставщики смогут оперативно
   проверять качество закупаемых продуктов. Это гарантирует использование только
   свежих ингредиентов для приготовления блюд, что напрямую влияет на их вкус,
   презентацию и общее впечатление гостей.

## Формат входных и выходных данных

**Входные данные.** Система принимает на вход реальные изображения фруктов и
овощей в .jpg и .png формате. Каждое изображение относится к одному из двух
классов: fresh (свежий) и frotten (несвежий).

**Выходные данные.** На выходе система возвращает вероятность принадлежности
входного изображения к одному из двух классов fresh или rotten, а также сам
класс.

## Метрики

В задаче используется метрика accuracy. Поскольку датасет сбалансированный, то
accuracy хорошо подходит. Целевое качество модели — accuracy >95% на тестовом
наборе данных. Такое целевое значение обусловлено анализом имеющихся в открытом
доступе решений подобных задач.

## Валидация и тест

Поскольку в исходном датасете есть только train и test части, “возьмем” от train
15% объектов. Во время валидации мы смотрим, как падает loss и растет accuracy.
Для визуализации используется система логирования MLFlow.

## Датасеты

Для решения задачи оценки качества продуктов будет использоваться следующий
[датасет с Kaggle](https://www.kaggle.com/datasets/swoyam2609/fresh-and-stale-classification).

- **Общий объем датасета:** 30357 наблюдений.
- **Общий объем данных:** ~3.1 Гб.
- **Распределение целевой переменной (%fresh/%rotten):**
  - 48/52 - train+test
  - 47/53 - train
  - 48/52 - test

## Моделирование

### Бейзлайн

- Архитектура: 4 сверточных слоя (Conv2d + BatchNorm2d + MaxPool2d) + 2 линейных
  слоя.
- Функция потерь: CrossEntropyLoss.
- Оптимизатор: Adam.
- Метрика качества: Accuracy.
- Число эпох: 15

### Основная модель

- Ссылки на модель
  - ResNet18 [[arXiv](https://arxiv.org/abs/1512.03385)] с отброшенными
    полносвязными слоями.
  - [Реализация в PyTorch](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.resnet18.html)

- Способ обучения:
  - Предобработка данных: аугментации; нормализация.
  - Функции потерь: CrossEntropyLoss.
  - Оптимизатор: Adam.
  - Планировщик: ReduceLROnPlateau для уменьшения learning rate при плато.
  - Метрики: Accuracy.
  - Регуляризация: Dropout.

## Внедрение

Предполагается использование модели в двух видах:

- С помощью скрипта одноразового запуска для быстрого запуска инференса на одном
  изображении.
- С помощью Triton сервера для удобства взаимодействия пользователей с
  приложением.

## Setup

```shell
# Клонирование репозитория
git clone git@github.com:sidtim/fresh-rotten-classification.git
cd fresh-rotten-classification

# Установка и активация окружения Conda
conda create -n tas-test-project python=3.12.12 -y
conda activate tas-test-project

# Установка Poetry
pip install poetry

# Установка зависимостей
poetry install

# Запуск pre-commit проверок
poetry run pre-commit run -a

# Запуск mlflow сервера для трекинга экспериментов
mlflow server --host 127.0.0.1 --port 8080
```

## Train

```shell
# Запуск обучения бейзлайна
poetry run python run_training.py model.type=simple_cnn training.max_epochs=15

# Запуск обучения предобученной ResNet18 (по умолчанию запускается именно эта модель)
poetry run python run_training.py training.max_epochs=15

# СОВЕТ: можете сократить число эпох с 15 до 3. В целом задача легкая и приемлемое качество достигается на малых эпохах.
```

После запуска run_training.py происходит следующее:

1. Автоматически скачиваются данные для обучения модели из S3-хранилища с
   помощью функции `check_and_download_data`.

- `Внимание!` Хотелось бы обратить особое внимание на то, что в файле
  `.dvc/config` я выложил ключи к S3. Эти ключи я создал для сервисной учетной
  записи у которой есть права только на чтение данных из S3. Я не нашел другого
  способа как организовать для проверяющего доступ к S3, чтобы предварительно с
  ним не связываться. На мой взгляд все сделано безопасно, потому что у учетки
  только права на чтения. С целью злого умысла эти ключи использовать не
  получиться.

2. Задаются настройки логирования экспериментов в MLFlow с помощью функции
   `setup_mlflow`.
3. Инициализируется DataModule через который происходит передача данных в
   модель.

- В процессе передачи данных для обучения изображения проходят следующую
  предобработку: Resize, RandomHorizontalFlip, RandomRotation, ToTensor,
  Normalize.
- В процессе передачи данных для валидации и тестирования изображения проходят
  следующую предобработку: Resize, ToTensor, Normalize.

3. Запускается обучение модели. В процессе обучения и тестирования ключевые
   метрики логируются в MLFlow по адресу `localhost:8080`
4. Лучшие экземпляры модели сохраняются в папку `./checkpoints/`.
